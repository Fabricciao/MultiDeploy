# 04 — IA : saisie vocale, saisie par photo, affiches, charte

## 0. Principes
1. **Interfaces de fournisseur** : `SpeechToText`, `StructuredExtractor` (texte et vision), `Translator`, `ImageProvider`, `PosterRenderer`. Chaque implémentation est interchangeable par configuration (par tenant si besoin).
2. **Sortie structurée garantie** : schémas Zod/JSON Schema ; sortie invalide → réparation automatique 1 fois, sinon revue manuelle.
3. **Humain dans la boucle** : l'IA remplit un brouillon, jamais un enregistrement final.
4. **Mesure** : chaque appel journalisé dans `ai_usage` → crédits par agence.
5. **Confidentialité** : audio/photos supprimés après traitement selon la rétention de l'agence ; aucun entraînement sur les données ; mention claire dans l'UI.

Les tarifs et noms exacts de modèles évoluent vite : le spec fixe les **rôles** (STT, LLM multimodal, génération d'image) et laisse le choix du fournisseur à un benchmark réalisé en phase 0 sur vos propres échantillons.

## 1. Saisie par dictée vocale (nouveau client ou nouveau bien)

### 1.1 Expérience
1. Bouton micro flottant (« Nouveau → Dicter ») accessible partout, surtout sur mobile.
2. Choix implicite client/bien : l'IA détecte l'intention (« j'ai un acheteur… » vs « j'ai un 4 pièces rue… ») ; l'utilisateur peut forcer le type.
3. Enregistrement avec niveau sonore visible, pause/reprise, compte à rebours max 3 min. Astuce affichée une fois : *« Parlez naturellement : nom, téléphone, ce que cherche le client, budget… »*.
4. Traitement (≈ 5–10 s) avec squelette du formulaire qui se remplit progressivement.
5. **Écran de revue** : formulaire normal pré-rempli ; chaque champ rempli par l'IA a un indicateur discret de confiance (neutre / à vérifier en ambre), et un survol/clic affiche **l'extrait de la dictée** qui l'a justifié. Champs manquants obligatoires listés en haut (« Il manque : téléphone »).
6. Option « Compléter par la voix » : un second enregistrement complète sans écraser les champs déjà validés.
7. Enregistrer → fiche créée ; la transcription est attachée à la timeline (note interne) si l'agent le souhaite.

### 1.2 Pipeline technique
```
MediaRecorder (webm/opus ou mp4/aac)  →  upload Storage (org/{id}/intake/…)
   →  POST /api/ai/intake {kind:'voice', target:'contact'|'property'|'auto'}
   →  job ai_jobs(queued)
   →  STT (multilingue, hébreu+français mélangés, noms propres, chiffres)
   →  Normalisation (nombres en lettres FR/HE → chiffres, "trois pièces et demie" → 3.5,
        "un million deux cent mille shekels" → 1_200_000 ILS, téléphones → E.164)
   →  LLM extraction → JSON strict (schéma ci-dessous) + confidence + evidence par champ
   →  Résolution d'entités : ville/quartier → geo_places (alias FR/HE/EN),
        doublon contact (téléphone/nom flou) → proposition "Existe déjà : ouvrir ?"
   →  ai_jobs.status = needs_review → Realtime → UI
```
- **Langues** : entrée FR, HE, EN et **mélange** dans une même phrase (très courant). Le prompt d'extraction impose des champs en forme canonique (codes, nombres), indépendamment de la langue source.
- **Vocabulaire du domaine** injecté au prompt : mamad, soukka, tabu, arnona, va'ad bayit, machsan, TAMA 38, noms de villes/quartiers (depuis `geo_places`), prénoms usuels pour guider la transcription.
- **Mode dégradé** : si l'IA échoue → la transcription brute est conservée en note, formulaire vide, message clair (rien n'est perdu).
- Alternative légère en direct (Web Speech API) rejetée pour l'hébreu : support navigateur inégal, pas de contrôle.

### 1.3 Schéma d'extraction (extrait Zod conceptuel)
```ts
const FieldMeta = z.object({ confidence: z.number().min(0).max(1), evidence: z.string().optional() });

const ContactIntake = z.object({
  first_name: z.string().nullable(), last_name: z.string().nullable(),
  first_name_he: z.string().nullable(), last_name_he: z.string().nullable(),
  phones: z.array(z.string()), emails: z.array(z.string()),
  preferred_locale: z.enum(['fr','he','en']).nullable(),
  kinds: z.array(z.enum(['buyer','seller','landlord','tenant','investor','other'])),
  aliyah_status: z.enum(['pre_aliyah','recent','resident','none']).nullable(),
  search: z.object({
    transaction: z.enum(['sale','rent']).nullable(),
    property_types: z.array(z.string()),
    cities: z.array(z.string()), neighborhoods: z.array(z.string()),
    budget_min: z.number().nullable(), budget_max: z.number().nullable(), currency: z.enum(['ILS','USD','EUR']).nullable(),
    rooms_min: z.number().nullable(), rooms_max: z.number().nullable(),
    area_min: z.number().nullable(), floor_min: z.number().nullable(),
    must_have: z.array(z.string()), nice_to_have: z.array(z.string()),
    move_in_by: z.string().nullable(),
  }).nullable(),
  financing: z.object({ mortgage_approved: z.boolean().nullable(), amount: z.number().nullable() }).nullable(),
  notes: z.string().nullable(),
  source: z.string().nullable(),
  _meta: z.record(z.string(), FieldMeta),   // confiance + extrait par champ
  _missing_required: z.array(z.string()),
});
// PropertyIntake : même principe (adresse, type, pièces, surfaces, étage, prix, options, mandat, propriétaire…)
```
Règle d'or du prompt : *« Ne jamais inventer. Si l'information n'est pas dite, `null`. Ne pas déduire un budget d'un quartier. »*

### 1.4 Jeu d'évaluation (indispensable)
Constituer **30 à 50 dictées réelles anonymisées** (FR, HE, mixtes, bruit de rue, accents) avec la vérité terrain ; métriques : exactitude par champ, taux de champs inventés (cible 0), temps total. Exécuté en CI à chaque changement de prompt/modèle (`evals/`).

## 2. Saisie par photo d'un papier manuscrit

### 2.1 Expérience
1. « Nouveau → Scanner un papier » : caméra plein écran avec cadre guide, prise multiple (plusieurs pages), import depuis la galerie ou capture d'écran WhatsApp/PDF.
2. Pré-traitement **côté client** : détection des bords, redressement de perspective, amélioration du contraste, compression (≤ 1,5 Mo/page) — rapide et économique.
3. Traitement vision (≈ 8–15 s) → écran de revue identique à la dictée, avec **l'image source affichée à côté** ; clic sur un champ = encadré de la zone d'origine sur l'image si disponible.
4. Types de papier gérés : fiche client manuscrite, carte de visite, notes sur bloc, fiche de bien imprimée (promoteur), capture d'annonce, tableau Excel photographié.

### 2.2 Pipeline
```
Capture → redressement/compression (client) → upload → ai_jobs(intake_photo)
 → LLM multimodal (lecture manuscrit hébreu/français/anglais + extraction directe vers le schéma)
 → (option) OCR classique en second avis pour numéros de téléphone/prix (vérification croisée)
 → validations déterministes (téléphone valide E.164, prix plausible, pièces entre 1 et 12…)
 → needs_review
```
- **Vérification croisée des nombres** (téléphone, prix, surface) : le modèle donne la valeur ; une seconde passe de lecture ciblée confirme ; en cas de désaccord → champ marqué « à vérifier ».
- Gestion des papiers **bilingues** (hébreu de droite à gauche + chiffres latins) explicite dans le prompt.
- Photo floue/illisible → message guidé (« reprendre en meilleure lumière ») au lieu d'une extraction hasardeuse.

### 2.3 Import en masse
Même moteur pour un lot de photos ou un PDF/Excel : file de jobs, tableau de revue en grille (valider ligne par ligne ou tout accepter ≥ seuil de confiance).

## 3. Génération de contenus (textes)
- **Rédaction d'annonce** : à partir des champs du bien, 3 tons (sobre, chaleureux, premium), longueur au choix, dans chaque langue — avec règles : pas d'affirmation non fondée (« vue mer » seulement si coché), pas de superlatifs interdits, respect du champ « mentions légales ».
- **Traduction FR↔HE↔EN** avec glossaire immobilier par agence (ex. « mamad » conservé / traduit « pièce sécurisée »), badge « traduit par IA » jusqu'à relecture.
- **Légendes réseaux sociaux** : texte + hashtags localisés (villes/quartiers) + appel à l'action avec lien/QR.
- **E-mail personnalisé** : intro générée à partir du profil client (« Voici 3 biens qui correspondent à votre recherche à Netanya… »), modifiable avant envoi.

## 4. Affiches publicitaires (Facebook / Instagram)

### 4.1 Approche hybride (choix clé)
| Couche | Produit par | Pourquoi |
|---|---|---|
| Fond / ambiance / scène | **Modèle d'image IA** (famille `gpt-image-*` par défaut, interchangeable) | Variantes visuelles, étirement de la photo au format Story, amélioration lumière/ciel, mise en scène virtuelle (étiquetée) |
| Textes (prix, pièces, m², ville, slogan), logo, QR, mentions légales | **Moteur de template déterministe** | Les modèles d'image écrivent mal le texte, **encore moins l'hébreu RTL** ; un prix faux sur une affiche est inacceptable |
| Cohérence de marque | **Brand kit** | Couleurs, polices, positions, coins arrondis, ton |

### 4.2 Parcours « Générer l'affiche » (1 bouton sur la fiche du bien)
1. Clic **« Créer une affiche »** → panneau latéral.
2. Pré-sélections intelligentes : photo de couverture, **format** (Facebook 1200×630 / Instagram 1080×1080 / Portrait 1080×1350 / Story 1080×1920 / A4), langue (par défaut langue du public cible de l'agence ; option bilingue HE+FR côte à côte), template recommandé selon le format.
3. Choix du **niveau d'intervention IA** :
   - *Fidèle* : photo réelle + habillage de marque (0 crédit image, instantané).
   - *Amélioré* : IA retouche lumière/ciel/netteté, étend l'image aux proportions voulues.
   - *Créatif* : IA génère un fond/ambiance autour de la photo réelle (texture, dégradé, décor d'ambiance cohérent avec la charte).
4. Personnalisation rapide : 3 variantes de mise en page, accroche proposée (modifiable), éléments à afficher (prix, adresse partielle, contact, QR vers la page publique).
5. Génération → 2–4 variantes en grille → favori → **télécharger / copier la légende / partager**. Historique conservé sur le bien.
6. Les affiches sont **rattachées au brand kit versionné** : si la charte change, bouton « Régénérer avec la nouvelle charte ».

### 4.3 Garde-fous (éthique et légal)
- **Ne jamais altérer la réalité du bien** dans le mode créatif : l'IA ne modifie pas la structure, surface, vue, état du bien. Toute **mise en scène virtuelle** (meubles ajoutés, ciel remplacé) est étiquetée sur l'affiche (« Image retouchée / mise en scène virtuelle ») — réglable par l'admin mais activé par défaut.
- Filtre de sécurité des prompts, pas de personnes identifiables générées, pas de logos tiers.
- Mentions légales de l'agence automatiquement apposées (champ obligatoire du brand kit pour activer la génération).
- Cible de coût affichée avant génération (« ≈ 3 crédits »).

### 4.4 Rendu & export
- Moteur de template (voir `02-architecture.md` §8) : grille, safe areas Instagram/Story, texte auto-ajusté (fit) en FR/HE, chiffres et symboles `₪` correctement orientés, polices incorporées.
- Sorties : PNG/JPEG (qualité réglable), PDF (A4), pack « multi-format » en un clic (Post + Story + Facebook) dans un ZIP.
- Stockage `org/{id}/posters/{generation_id}/…` ; EXIF retiré.

### 4.5 Phase ultérieure
- Publication directe Facebook Pages/Instagram (Meta Graph API, revue d'application Meta nécessaire), planification, UTM + QR de suivi.
- Courte vidéo/Reel (diaporama animé des photos avec musique libre de droits) via moteur de rendu vidéo — optionnel.

## 5. Charte graphique automatique

### 5.1 Objectif
À partir de l'URL du site d'une agence (et/ou d'un logo), produire en quelques secondes une **charte exploitable** : couleurs, polices, ton, logo, et l'appliquer au **thème du CRM** et aux **affiches / e-mails**.

### 5.2 Pipeline
```
URL  →  fetcher durci (anti-SSRF, timeout, taille max)
     →  HTML + CSS : theme-color, variables CSS (--primary…), couleurs récurrentes,
        polices (font-family computées, liens Google Fonts), favicon/apple-touch-icon, og:image
     →  capture d'écran (rendu headless) de la page d'accueil
     →  extraction des couleurs dominantes + quantification (k-means / palette) sur logo & capture
     →  recherche du logo : <img> en en-tête (alt/class "logo"), SVG inline, meta, favicon HD
     →  LLM vision : à partir de la capture + signaux ci-dessus, propose
        { couleur primaire, secondaire, accent, neutres, police titres/corps,
          style (arrondis, densité), ton éditorial, secteur de gamme }
     →  Génération de la palette complète en OKLCH (échelles 50–950)
     →  Contrôles : contraste WCAG AA des paires texte/fond, daltonisme, repli automatique
     →  Aperçu en direct (mini-CRM + une affiche d'exemple) → ajustements manuels → "Appliquer"
```
- **Fallbacks** : pas de site → upload logo → couleur dominante ; pas de logo → monogramme généré ; polices non libres → équivalent Google Fonts le plus proche (**hébreu inclus** : Heebo, Rubik, Assistant, Frank Ruhl Libre, Noto…).
- **Deux usages séparés, une seule source** :
  - *Thème CRM* : on n'applique que `primary`, `accent`, `radius`, `logo` — **les couleurs sémantiques (succès/alerte/erreur, statuts) restent fixes** pour la lisibilité et l'accessibilité. Garde-fous : si la couleur choisie n'a pas assez de contraste, l'app propose automatiquement une variante plus sombre/claire.
  - *Marketing* : palette complète, polices, formes, mentions légales pour affiches et e-mails.
- Charte **versionnée** (retour arrière), modifiable manuellement (sélecteur de couleurs, upload de polices, réglage d'arrondis), duplicable.
- Bouton « Réinitialiser au thème neutre ».

### 5.3 Mise en œuvre du thème
Variables CSS (`--color-primary-500`, …) injectées côté serveur selon `organization_id` dans le `<html>` (aucun flash au chargement), compatible mode clair/sombre ; tokens sémantiques (`--bg`, `--surface`, `--text`, `--accent`) calculés depuis la palette OKLCH.

## 6. Matching intelligent (assisté par IA, mais déterministe d'abord)
- Base : scoring SQL (voir `01-produit.md` §2.5).
- Couche IA optionnelle : explication en une phrase du pourquoi (« 4 pièces à Raanana, dans le budget, avec mamad ; étage 1 au lieu de ≥ 3 souhaité »), et suggestion d'assouplir un critère (« 6 biens de plus si budget +5 % »).

## 7. Coûts IA — ordres de grandeur (à re-vérifier au moment du build)
| Action | Usage | Ordre de grandeur |
|---|---|---|
| Dictée 1 min | STT + extraction | quelques centimes de $ |
| Photo manuscrite | 1 appel vision | quelques centimes de $ |
| Traduction d'une annonce | LLM texte | < 1 centime de $ |
| Affiche en mode Fidèle | 0 appel image | ≈ 0 |
| Affiche Amélioré/Créatif | 1 à 4 images | de l'ordre de 0,05 à 0,5 $ selon qualité/variantes |
| Extraction de charte | 1 appel vision + rendu | quelques centimes de $ |

→ Les **crédits IA** inclus dans chaque plan couvrent l'usage normal ; les affiches « créatives » sont le principal poste de coût et justifient la facturation au crédit.
