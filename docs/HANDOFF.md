### Procédures
- **Mettre à jour le code** : push ; `vps_docker_start` sur `multideploy` (relance `code`+`migrate`, vérifier `HEAD is now at <commit>` dans les logs de `code-1` et « MIGRATIONS DONE ») ; puis `vps_docker_update` sur `mdapp` (recrée `builder` → recompile si le commit a changé → `web`). Vérifier `vps_docker_containers` (`web` « healthy ») et `curl https://admin.nadlanhub.cloud/api/health`. Compter ~1 min de recompilation, avec une brève coupure.
- **Changer une variable, le compose ou la branche suivie** : `vps_docker_create` avec le **contenu complet + l'environnement complet** (il remplace tout ; `vps_docker_update` ne prend aucune nouvelle config). Les conteneurs sont recréés, les volumes nommés (dont `md_db`) sont conservés — vérifié (« Skipping initialization », migrations en « skip »). Relire d'abord la config avec `vps_docker_get` (les secrets y figurent : ne jamais les recopier dans le chat ni dans git).
- **Pas d'exec direct** sur le VPS : pour inspecter la base ou générer un lien, créer un projet temporaire `mdprobe` (réseau externe `multideploy_default`, requête `psql` ou `curl http://gotrue:9999/...`), lire ses logs, puis le **supprimer** (`vps_docker_delete`). **Sans recopier de secret** : `env_file: [/docker/multideploy/.env]` (le fichier existe sur l'hôte) et, pour GoTrue, fabriquer dans le conteneur un JWT `service_role` signé HS256 avec `JWT_SECRET` (alpine + `apk add curl openssl`, valable 10 min). `environment` du create : une variable non secrète (ex. `EMAILS=…`).
- **Lien de connexion à usage unique** (secours) : `POST http://gotrue:9999/admin/generate_link` (`{"type":"magiclink","email":…}`, clé service) depuis `mdprobe`, puis `https://admin.nadlanhub.cloud/auth/callback?token_hash=<hashed_token>&type=magiclink&next=/fr` (≈ 1 h, usage unique). **Se connecter avec ce lien à la place de l'utilisateur exige son accord explicite** (le garde-fou de la session le bloque sinon) ; ensuite Playwright (`storageState`) permet de piloter l'interface.
- **Pièges** : `sleep` > ~20 s bloqué dans l'outil Bash ; les logs Hostinger (`vps_docker_logs`) s'accumulent et deviennent énormes (> 100 000 caractères) : l'outil les sauvegarde dans un fichier, les extraire avec Python (`json.loads`, filtrer `service == "code-1"` etc.) plutôt que de tout lire ; `$` doublé (`$$`) dans les commandes compose ; `environment` de `vps_docker_create` jamais vide ; Next derrière proxy → `lib/origin.ts` (`publicOrigin`) ; un fichier `"use server"` ne peut exporter que des fonctions async ; `git stash` + build local → conflit sur `next-env.d.ts` (le restaurer avant `stash pop`) ; le mode dev Next boucle si `.next` est périmé ; le proxy du bac à sable bloque les hôtes non autorisés (403 « CONNECT tunnel failed »).
